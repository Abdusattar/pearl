# Модуль «Дети» — заведение объекта с нуля, доступ по объектам, навигация

> Зафиксировано: 2026-08-28 (онбординг Школы, org_id=2)

## Заведение нового объекта (класса+дети) — только миграцией, не UI

В системе нет экрана управления группами/классами — даже 6 групп Садика
Сокулук когда-то занесены напрямую в БД, не через форму (решено 05.08, см.
[[architecture/billing_module]] контекст). Для Школы (org_id=2) — тот же
путь: `scripts/import_school_students.py`, разовый скрипт, не постоянная
фича. Обоснование, что не строить CRUD ради вещи, которая меняется раз в
год — сознательное решение, не недоделка.

**Источник данных** — 19 `.docx`-файлов от Айжан (`data/школа дети/`), по
одному на класс/поток, сведены вручную в `school_import_review.csv`
(ФИО разбито на Фамилия/Имя/Отчество, ИНН, класс) — таблица показана
владельцу на сверку ДО записи в БД (тот же принцип, что
[[feedback_prod_data_writes_show_diff]]).

**Именование классов — цвет→буква, не с потолка.** Школа реально называет
классы по цвету (Red/Orange/Purple/Green/Yellow/Blue), не литерами — это
выяснилось только при разборе файлов, разошлось с предположением 05.08
(«классы с литерами 1А/1Б»). Решено с владельцем: красный=А, зелёный=Б,
фиолетовый=В, оранжевый=Г, жёлтый=Д, голубой=Е — стандартная школьная
конвенция, не собственное изобретение.

**3 класс — два разных набора, не дубли.** Метки «3/11» и «3/12» в файлах
оказались 11-летней/12-летней программой обучения (переход по решению
Минобразования КР в этом учебном году) — то есть в 3 классе реально 7
параллелей, не 4. Проверено запросом: списки ФИО между «3/11» и «3/12»
одного цвета не пересекаются вообще (0 совпадений) — значит это точно
разные дети, не задвоенный/битый экспорт одного класса. Буквы у каждого
потока начинаются заново («3-А(11)», «3-А(12)»), не продолжают алфавит —
так это называют в самой школе, после уточнения владельцем.

**Идемпотентность импорта** — по ИНН (`Student.extra["inn"]`); для детей
без ИНН в исходных файлах — по `(org_id, last_name, first_name,
patronymic)`. Даёт возможность безопасно перезапускать скрипт (было
нужно на практике — первый прогон на dev упал на кодировке кириллицы
Ө/Ү/Ң, чинили и гоняли повторно).

**Итог 28.08:** 19 групп, 332 ребёнка, 332 зачисления
(`start_date=2026-09-01`, начало учебного года), PIN 0136–0467, 2 ребёнка
без ИНН в исходных файлах (дописать, если появится).

## Доступ по объектам — `PILOT_USER_ORG_IDS`, не общий `PILOT_ORG_IDS`

До 27.08 пилот ограничивал ЧЕТЫРЁХ человек (Сатар/Мунара/Айдай/Талас)
ОДНИМ общим множеством объектов (`PILOT_ORG_IDS = {4}`). С открытием
Школы понадобился разный доступ разным людям одновременно — переведено
на `dict[user_id, set[org_id]]` в `app/dependencies.py`:

```python
PILOT_USER_ORG_IDS: dict[int, set[int]] = {
    1: {2, 4},  # Сатар (разработчик)
    3: {4},     # Мунара (управляющая садиками)
    5: {2, 4},  # Айдай (совладелец)
    6: {2, 4},  # Талас (совладелец)
}
```

Заодно убран известный техдолг-дубль в `app/routers/expenses.py` — своя
копия `get_accessible_orgs`/`resolve_org` со старыми несуществующими id
(61/64 вместо 5/6, баг с 13.07, см. [[architecture/billing_module]]) —
теперь импортирует общую функцию из `dependencies.py`, дублирования
логики между двумя файлами больше нет.

Директор объекта (`role=director`, напр. Айжан — `organization_id=2`)
видит только свой объект — эта ветка не менялась, работала на Школу
ещё до онбординга данных, просто раньше объект был пустой.

## Навигация теряет выбранный объект без `org_id` в ссылке

`resolve_org(org_id, user, db)` при отсутствии параметра `org_id` падает
на `user.organization_id` («домашний» объект пользователя) — это
единственный фолбэк, никакой сессии/куки с последним выбором нет.
Выбор объекта через `<select class="org-select">` в шапке (`base.html`)
работал, потому что его JS сам дописывает `?org_id=` в URL при смене —
но ссылки сайдбара и нижней мобильной навигации этого не делали вообще,
у них были голые `href="/students/"` и т.п.

**Почему не проявлялось до 28.08:** все четверо пилотов были ограничены
ОДНИМ объектом — повторный переход всегда возвращал туда же, разницы
никто не видел. Открытие Школы сделало Сатара (и Айдай/Талас) реальными
мультиобъектными пользователями впервые — баг проявился в первую же
минуту («переключился на Школу, нажал «Дети» — вернуло на Садик»).

**Фикс** — каждая ссылка сайдбара/bottom-nav в `base.html` теперь несёт
`{% if current_org_id %}?org_id={{ current_org_id }}{% endif %}`, тем же
паттерном, что уже использовал сам селектор. `current_org_id` уже
передавался в контекст шаблона почти всеми роутерами (кроме `auth.py`,
где он и не нужен) — не потребовалось трогать ни один router, только
сам `base.html`.

**Урок на будущее:** при появлении второго/третьего реально
мультиобъектного пользователя (не пилота с одним объектом) — сразу
проверять, переживает ли выбор объекта переход по ЛЮБОЙ ссылке
навигации, а не только по тем, что уже кто-то тестировал вручную.
